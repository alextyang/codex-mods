## Keychain isolation (ARCHITECTURE §5.3): binary patch `keychain-service-name`

The copy asked macOS for the STOCK app's login-keychain item "Codex Storage Key". Static analysis (builder/KEYCHAIN.md, re-derived here with
`adapters/tools/binary-patch.mjs`; no app launched, no Keychain command run):

- The service is `"Codex" + " Storage Key"`, the account is `"Codex"`. `"Codex"` is **not data**: it is assembled from instruction immediates in
  `Frameworks/Codex Framework.framework/Versions/155.0.8059.40/Codex Framework`, so no plist key, ini value, env var or asar edit can change it.
- The earlier `keychain-service` transform (asar `package.json` `productName` → "Codex Mods") was **ineffective** (the prompt still named
  "Codex Storage Key") and is **removed**. `productName` is needed for nothing else (the JS `app.setName("ChatGPT")` overrides the name that matters to the app),
  so there is no remaining asar edit for the keychain.
- Locator chain: the C string `" Storage Key\0"` occurs exactly once (in `__TEXT,__const`, pooled with `use-mock-keychain`/`saltysalt`, not in `__cstring`);
  one ADRP+ADD reference in `__text` (0x104b954); in that function the signature
  `movz w8,#0x6f43 ; movk w8,#0x6564,lsl 16 ; str w8,[xN,#a] ; movz w8,#0x78 ('x') ; strh w8,[xN,#b]` occurs exactly twice:
  the **service** (base `sp`, just before the reference) and the **account** (base `x26`, 0x884 earlier). Nothing else matches in the function window.
- Patch: the two `movz w8,#0x78` words become `movz w8,#0x79` ('y'), giving **"Codey Storage Key" / account "Codey"**.
  Encoding check: `movz wD,#imm16` = `0x52800000 | imm16<<5 | D`, so `#0x78` → `0x52800f08` (bytes `08 0f 80 52`) and `#0x79` → `0x52800f28` (bytes `28 0f 80 52`);
  only the low byte of the little-endian word changes. Offsets (file = vmaddr in `__TEXT`): service **0x104b94c**, account **0x104b0dc**.
- `adapter.json` `binaryPatches` carries four entries (two Codey, two Aura) applied **in array order to the same file**: `keychain-service-name` (service, offset 0x104b94c) then
  `keychain-service-name-account` (0x104b0dc). `sha256Before`/`sha256After` are of the whole framework binary; the second entry's `sha256Before` is the first's
  `sha256After` (a chain). File path is relative to `Contents/` and uses the real version directory, not `Versions/Current`. The builder must re-sign afterwards.
- Future builds: `generate-adapter.mjs` re-derives both entries by following the xref chain; it fails closed (reports `binaryPatches:keychain-service-name` as
  missing and emits nothing) unless the string, its single reference and exactly two name signatures are found. Tests cover this on a synthetic Mach-O and on the installed 20156 framework.
- **Aura fallback , also mandatory.** When the copy's own item is missing the same function falls back to another OpenAI app's item, service "Aura Safe Storage" / account "Aura".
  The service is 17 characters: 16 are copied from the shared data string (`Aura Safe Storage\0` @0xe26f44c, ADRP+ADD @0x104ba04) and the last is an immediate `mov w9,#0x65 ('e')` + `strh w9,[x22,#0x10]` @0x104ba18;
  the account is built from immediates `mov w8,#0x7541 ('Au')` + `movk w8,#0x6172,lsl 16 ('ra')` @0x104bab8/0x104babc (the data string `Aura\0` @0xe26f45e is only used for an overlap check at 0x104baa4).
  The data strings are shared with the browser-profile importer and are NOT modified. Patches: `aura-fallback-service` @0x104ba18 `a90c8052`→`c90c8052` (`movz w9,#0x66`, "Aura Safe Storagf") and
  `aura-fallback-account` @0x104babc `482eac72`→`484eac72` (`movk w8,#0x6272,lsl 16`, "Aurb"), chained after the two Codey patches on the same framework file (array order: Codey service, Codey account, Aura service, Aura account).
  Derivation: the Aura string and its single reference must exist exactly once and lie within 0x800 bytes of the Codey reference, then exactly one immediate pattern each; otherwise the generator refuses to emit the pack.
- Not verified natively: that the patched framework runs and creates/uses "Codey Storage Key" . `--use-mock-keychain` remains the way to avoid any prompt in QA.

## Framework views need the app's own preload (static finding)

App windows are created with `webPreferences.preload` = `<app.asar>/.vite/build/preload.js` (it exposes the app's bridge and the Sentry IPC; the path is passed
into the window manager from the bootstrap chunk). `framework/main/electron-adapter.cjs` creates `WebContentsView`/`BrowserWindow` with only
`{sandbox, contextIsolation, nodeIntegration:false}`, so an `app://-/index.html?initialRoute=…` framework view has no app bridge and cannot boot. The default view
background is transparent, which matches "view-open succeeded, nothing visible". The adapter must set the same `preload` (and the app's session) on views it creates.

(47 ids: `keychain-service-name`, `keychain-service-name-account`, `aura-fallback-service`, `aura-fallback-account`, `cua-relocate-dir`, `cua-relocate-config`, `cua-relocate-installer`, `cua-relocate-approvals`, `cua-disable-locked-use`, `cua-helper-private-home`, `managed-config-no-persist`(+`-cua-repl`, `-cua-repl-thread`), `cua-service-path-env`, `cua-container`, `cua-bundle-id:*`, `cua-container:*`), and

Static analysis only (asar JS, the helper app, node_repl, the cua/sky packages; no launches). Every file under `Contents/` was searched with code-signature blobs of every slice excluded.

### 1. How the app computes, installs and launches the helper (main bundle `main-CqEoQDOU.js`)

- `Da(codexHome)` = `<codexHome>/computer-use/Codex Computer Use.app` is the ONLY place the canonical helper directory is computed (`Ta` = `Codex Computer Use.app`). It is used by
  1. `Oie({sourceServiceAppPath, codexHome})`: at startup removes `Da(codexHome)` and `ditto`s the bundled helper (`Mie()`, `Resources/cua_node/lib/node_modules/@oai/sky/Codex Computer Use.app`) into it, unless `CODEX_ELECTRON_SKIP_COMPUTER_USE_CANONICAL_REFRESH=1`;
  2. `Na`/`tne`: service-path discovery for node_repl: `process.env.SKY_CUA_SERVICE_PATH` first, else `Da(codexHome)` if it exists; the result is exported to node_repl by `ene()` as `SKY_CUA_SERVICE_PATH`;
  3. `de=new kie(Da(codexHome),…)`: the managed service class spawns `<dir>/Contents/MacOS/SkyComputerUseService` and compares running processes with that path.
- **Three more paths join `computer-use` off the shared codexHome** (found by scanning every `computer-use` literal in all 285 non-renderer scripts of the asar, following constants and arrays into `join`/`resolve`):
  1. Helper overlay config: `kc({settingsStore,…})` → `Fc({codexHome:c.ot(),config})` → `Ic({dir,configPath,config})`. `Fc` computes `n=join(codexHome,Sc)` (`Sc=\`computer-use\``) and `r=join(n,Cc)` (`Cc=\`config.json\``) and writes the file atomically (tmp + rename, serialized per path).
     `kc` runs at startup (`ne=async e=>{…Ac(…)`), from the `computerUse`-related settings side effect (`Oc(e)&&Ac`), and on the app-server connection hook. Without a change the copy would overwrite `<CODEX_HOME>/computer-use/config.json`, the STOCK helper's overlay config (theme, accent colour, locale).
  2. Locked-use installer: `cT(arg)` runs `Vhe()` (`execFile`, arg `status` / `install` / `uninstall`, 2 min timeout), used by `sT()` (is `OK: installed`?) and `Bhe(bool)`. `Vhe()` = `join(codexHome, ...Phe)` with `Phe=[\`computer-use\`,\`Codex Computer Use.app\`,\`Contents\`,\`SharedSupport\`,\`Codex Computer Use Installer.app\`,\`Contents\`,\`MacOS\`,\`Codex Computer Use Installer\`]`;
     i.e. it is the installer inside the helper that `Da` names, and without a change the copy would run the STOCK installer (install/uninstall the stock authorization plugin).
  3. Legacy approvals migration `Hw(configTomlPath)` (reached through `Xme`/`Zme`, `uhe`/`che`): `join(dirname(<codexHome>/config.toml),\`computer-use\`,\`config.toml\`)`, read and then rewritten. It is **win32-only** (`Xw` returns the TOML path only for `platform==='win32'`; on darwin the approvals live in `~/Library/Group Containers/<container id>/…/ComputerUseAppApprovals.json`, already renamed by `cua-container`),
     so it is unreachable in the macOS copy; it is relocated anyway so that no `computer-use` path of the bundle derives from `CODEX_HOME`. This is the one ID beyond the two named in the change order.
  Examined and **not** a helper path: `join(e.pluginRoot,'skills','computer-use','SKILL.md')` in `Tne` (the bundled `computer-use` PLUGIN's skill text, under the plugin root that the app-server installs; it prepends "Record computer audio." when the audio feature is on, same as stock; shared plugin cache, not the helper's data);
  string ids such as `computer-use` MCP server/plugin names, `computer-use/stop-application`, `computer-use/${o}` (settings route) and the renderer chunks. `SKY_CUA_SERVICE_PATH` aside, nothing else in `main`, `src-*`, `worker.js`, `bootstrap`, `startup-requirements`, the preloads or `skills-*` builds a `computer-use` path.
- `SKY_CUA_SERVICE_PATH` is an **environment variable**, not a config key: the app reads it from `process.env` and passes it into node_repl's environment. No code in the app writes it to `config.toml`
  (a stock value can still reach the app through the user's environment, so the copy uses a distinct name).
- The node client (`@oai/cua` and `@oai/sky` `…/targets/mac/native-pipe.js`, identical copies) resolves the helper to launch as: `env.SKY_CUA_SERVICE_PATH`, else `<env.CODEX_HOME>/computer-use/Codex Computer Use.app` if it exists, else
  `{bundleIdentifier:"com.openai.sky.CUAService"}` via LaunchServices. On a daily profile `CODEX_HOME` is the shared `~/.codex`, and the bundle id resolves the STOCK helper: which is why the helper's identity and location are renamed and relocated.

## Managed tool sync no longer persists the copy's config (ARCHITECTURE §5.3)

Defect: at every launch the copy's upstream "managed tool sync" rewrote entries of the SHARED `~/.codex/config.toml` (and the shared plugin cache) to point into the copy; the stock app rewrote them back on its launch, so the CLI followed whichever app ran last.

**How it works upstream (static, 20156 `main-CqEoQDOU.js`).**
- `hc()` (called by `mc()` from the bundled-plugin reconciler `f()` at every reconcile: launch, desktop-feature change, `syncAfterPluginChange` on plugin install/uninstall) builds the node_repl definition with `ic()` → `ac()` → `E()` (`src-CP7XXlpZ.js`; `includePrivateProcessEnv:false`, no host-services pipe) and sends **`config/batchWrite`** through the app-server with the edits `mcp_servers.node_repl` (= that definition), `mcp_servers.cua_repl` (the disabled stub `{command: process.execPath, enabled:false}` or null) and null deletions of `shell_environment_policy.set.NODE_REPL_BROWSER_BACKENDS` / `…_TRUSTED_CODE_PATHS`.
- `rne()` (same pass) rewrites the **cua-repl plugin's `.mcp.json`** in the shared plugin cache (`<codexHome>/plugins/cache/openai-bundled/unified-computer-use/<ver>/.mcp.json`: `command`, `args`, `enabled`, `omit_tools_from`, `env` with `CODEX_CLI_PATH`, `NODE_REPL_*`, trusted services, `CUA_REPL_ENABLED_SURFACES`, all the copy's paths).
- The app also passes the same node_repl definition **per thread** (`_c()` → `thread/start` / `readCodexConfig` `config:{…}`, with the private env added); it does NOT pass `cua_repl` per thread when enabled (it lives only in the plugin file).
- `notify`: the app's JS writes it only on win32 (`Nre`, guarded `platform==='win32'`). **On macOS it is written by the helper binary**: `SkyComputerUseService` / `CUALockScreenGuardian` link a TOML library and carry a config model with `notify`, `previousNotify`, `mcp_servers`, `plugins`, `missingServerTable`, `missingPluginTable` and `--previous-notify`; it edits `<CODEX_HOME>/config.toml` (the `CODEX_HOME` of its environment). No asar transform can stop that.
- `Qc()` (codex_app plugin `.mcp.json`) is NOT copy-specific: it writes `command`/`cwd` inside the shared plugin cache and strips `CODEX_MCP_NODE_PATH` before writing (`delete o.env?.CODEX_MCP_NODE_PATH`); stock and copy compute the same file for the same plugin version. The copy's `codex_app` definition (with its own node path) travels per thread (`Xc`: `mcp_servers.codex_app.*`). Left as is.

**Experiment (UID503 on the QA machine, no model traffic).** Bundled `codex 0.162.0-alpha.17.2`, throwaway `CODEX_HOME` with the bundled `unified-computer-use` plugin cache (copied from a QA profile) enabled, `codex mcp list --json`:
| override | result |
|---|---|
| none | plugin server `cua_repl` listed with the plugin's command/args/env (15 env vars) |
| `-c mcp_servers.cua_repl.command="/usr/bin/true"` | **replaces the plugin-supplied definition**: `command=/usr/bin/true`, `args=[]`, env empty |
| `-c 'mcp_servers.cua_repl={command=…,args=[]}'` | same (replace) |
| `-c plugins."unified-computer-use@openai-bundled".mcp_servers.cua_repl.command=…` | no effect |
| `-c mcp_servers.cua_repl.env.CODEX_CLI_PATH=…` or `….enabled=false` (no command) | **error** `invalid transport in mcp_servers.cua_repl` (the top-level entry shadows the plugin one, so it must be a full definition) |
| `-c 'mcp_servers.cua_repl=<the plugin file's whole JSON as an inline table>'` | accepted (`enabled_tools`, `omit_tools_from`, `tools.js.output_token_limit`, `env_vars`, `env` all valid), replaces the plugin definition |
So a top-level override replaces a plugin-supplied server, i.e. option 1 is possible. **But a static pack template would be wrong for `cua_repl`**: its `enabled`, `CUA_REPL_ENABLED_SURFACES`, `NODE_REPL_TRUSTED_SERVICES` (browser and/or `sky`), `BROWSER_USE_AVAILABLE_BACKENDS`, `omit_tools_from` change at runtime with feature flags and with the user enabling Computer Use; a frozen baseline would drop the Computer Use surface in the copy. Hence:

**Decision implemented.**
- `managed-config-no-persist`: `hc` sends `gc(C).slice(1)` (only the `shell_environment_policy` deletions; no `mcp_servers.node_repl` / `mcp_servers.cua_repl` edit).
- `managed-config-no-persist-cua-repl`: `rne()` still computes the definition but does not write the plugin `.mcp.json`; it keeps a clone in `globalThis.__codexmodsCuaRepl` (null when cua_repl is not enabled).
- `managed-config-cua-repl-thread`: `_c()` adds that clone to the per-thread config as `mcp_servers.cua_repl` (full table; replaces the plugin-supplied definition by the experiment above) exactly where it already adds node_repl; when cua_repl is disabled the app's own stub (`Ia`) is used unchanged.
- All three are in `mandatoryEdits`; the generator derives them (fail closed) and refuses the pack unless `backend.configOverrides` is declared (`notify`, `mcp_servers.node_repl`, known template variables only).
- **`backend.configOverrides`** (Host adds one `-c` per key to the primary backend spawn): `notify = ["${computerUseDir}/Codex Computer Use.app/Contents/SharedSupport/SkyComputerUseClient.app/Contents/MacOS/SkyComputerUseClient", "turn-ended"]`, and `mcp_servers.node_repl` = `{command: ${resources}/cua_node/bin/node_repl, args: [], startup_timeout_sec: 120, env: {NODE_REPL_NATIVE_PIPE_CONNECT_TIMEOUT_MS, NODE_REPL_NODE_MODULE_DIRS, NODE_REPL_NODE_PATH, NODE_REPL_TRUSTED_CODE_PATHS = ${codexHome}:${resources}/cua_node/lib/node_modules, CODEX_HOME, CODEX_CLI_PATH = ${relayPath}, BROWSER_USE_CODEX_APP_BUILD_FLAVOR, BROWSER_USE_CODEX_APP_VERSION}}`.
  It is a baseline for readers that see no per-thread config; the app's per-thread `config` (full, dynamic env incl. backends list, host-services pipe, `SKY_CUA_SERVICE_PATM`) overrides it for threads. The conditional/dynamic env names are deliberately not in the baseline.
- Static guarantee (`persistedManagedConfig`, run in the generator's dry run and in the stock test): no `gc()` spread without `.slice(1)`, no `mcp_servers.cua_repl`/`node_repl` keyPath edit in any batchWrite list, no write in `rne`.

**The helper's own `notify` write (resolved).** The copy's own helper (relocated, renamed) edits the shared `config.toml` `notify` key with its own `SkyComputerUseClient` path (`--previous-notify` chaining), so `notify` can still flip between the stock helper's and the copy's value on disk. The pack's `notify` override gives the copy's backend the right value regardless. It is resolved by `cua-helper-private-home` (next section): the copy's helper gets a private `CODEX_HOME` (the helper reads the environment variable `CODEX_HOME`, `CodexHomeDirectory`; the same variable decides where it reads `computer-use/config.json`, see above). A same-length rename of the helper's `notify` key was considered and rejected for now (cannot verify statically that codex tolerates an unknown key or that the helper does not read it back).

## The copy's helper gets the profile directory as `CODEX_HOME` (ARCHITECTURE §5.3): `cua-helper-private-home`

Native evidence (a daily-profile Mac): after `managed-config-no-persist` the shared `notify` line still flipped to the copy's client when the helper started: the helper (`SkyComputerUseService` under `profiles/default/computer-use/…`) is a child of the copy's main process and inherits its environment (`CODEX_HOME=~/.codex`).

**How the helper is started (static).**
- The only start site in main/src/worker/bootstrap/preloads is `pd(path)`: `Xu({electronAppPath, resourcesPath}).spawnComputerUseService(path)`, the default `spawnService` of the managed-service class `kie` (`ensureServicePidForEnabledFeatures`: at enable/respawn, and for the worker's `computer-use-service-pid` RPC). `kie` only joins `<dir>/Contents/MacOS/SkyComputerUseService`; `Oie` (canonical refresh) only `ditto`s the bundle; `md`/`computerUseServiceProcessMatchesExecutablePath` only compares a pid's path.
- `spawnComputerUseService` lives in the native addon `Resources/native/sky.node`. It imports `posix_spawn`, `posix_spawnattr_*`, `responsibility_spawnattrs_setdisclaim` and `__NSGetEnviron`, and imports neither `NSProcessInfo`, `setenv` nor `NSTask`: the helper is **posix_spawned with the live C environment of the app process at call time** (not through LaunchServices/`open`, so the environment DOES propagate). **It is a Napi `AsyncWorker`** (`SpawnComputerUseServiceWorker`): the JS call returns a promise at once and `Execute()` runs `posix_spawn(path, argv={path}, attr(disclaim), *_NSGetEnviron())` LATER on a libuv worker thread (disassembly of `sky.node`, `Execute` at 0x3a9ec); there is no way to hand it an environment.
- No other site opens the helper: the only `/usr/bin/open` calls are open-in targets, the Chrome extension page and the app relaunch (`--env CODEX_HOME=…`, a different thing); the worker talks to the helper by Apple events on the pid it gets from main. `reopenNativeApp` (an addon export) is not referenced by any bundle.

**Edit (second version, after the native check of the first).** The first version swapped `process.env.CODEX_HOME` around the call and restored it when the call returned. Natively the helper still saw `~/.codex`: because the addon spawns asynchronously (above), the value was already restored when `Execute()` read the environment (the helper's environment showed `CODEX_MODS_COMPUTER_USE_DIR` set, so `pd` did run with the variable and the transform was in the asar). Now `pd` sets `process.env.CODEX_HOME = dirname($CODEX_MODS_COMPUTER_USE_DIR)` (= the profile directory; `layout.computerUse` is `<profileDir>/computer-use`), calls the addon, and then **keeps the value in place with the calling thread blocked** (`Atomics.wait` in 10 ms steps, no JS runs) until `/usr/bin/pgrep -P <our pid> -f /MacOS/SkyComputerUseService` reports a child that was not there before the call (bounded: 500 ms), and restores the app's own value (or its absence) in a `finally`; the addon's promise is returned unchanged. Because no JS runs while the profile dir is in place, nothing else (`c.ot()`, child spawns with the inherited environment) can observe it. If the child does not show up within the bound, the value is restored anyway (the helper then keeps the shared home, as before the fix, never a corrupted state). When the variable is unset nothing changes (the original call). Typical cost: one `pgrep` snapshot (~15 ms) plus ~10-25 ms of blocking at helper start.
Consequences for the helper: it writes `notify` into `<profileDir>/config.toml` instead of `~/.codex/config.toml`, and the file it reads as `<CODEX_HOME>/computer-use/config.json` is exactly the one `cua-relocate-config` writes (`$CODEX_MODS_COMPUTER_USE_DIR/config.json`). This also settles the earlier open question about the helper-side config path.
Fail closed: the generator refuses the pack unless `pd` has exactly the known shape, `spawnComputerUseService(` has exactly one call and `SkyComputerUseService` is named only in `kie`'s path join; after the dry run `helperStartSites` must find no start site outside a wrapper that sets the variable AND waits (`Atomics.wait`). The transform text contains no `String.replace` replacement pattern (`$&`, `` $` ``, `$'`, `$$`, `$n`), tested for every transform, so a builder that applies it with `.replace()` cannot corrupt it.

**Not covered (report).** node_repl can start the helper itself when no host-services pipe is available: `@oai/sky` `native-pipe.js` calls `nodeRepl.launchServices.openApplication({applicationPath|bundleIdentifier})`, i.e. LaunchServices, where the caller's environment does not propagate (the helper then starts with the default environment, not the profile `CODEX_HOME`). In the copy the host-services pipe is passed per thread, so this is a fallback only; it lives in the native `node_repl` binary, cannot be changed by an asar transform, and, if it happens, the helper may again write the default `~/.codex/config.toml`. Mitigation, if wanted: `open --env CODEX_HOME=…` is only available to callers we control (not here).

## `settings.section` exists on the General page only 

Native finding on the a daily-profile Mac: on Settings → Computer use the mount landed in that page's own sections container, which is laid out differently (the contribution became a squeezed flex item, one character per line); QA had only verified General (F7).
Decision (ARCHITECTURE): the anchor resolves on exactly one settings page, General, and is absent everywhere else.
- **Gate.** Every locator now starts with `body:has([data-settings-panel-slug="general-settings"][aria-current="page"])`: the navigation entry of the General page (`slug` `general-settings`, first slug of the Personal group in `settings-page-*.js`) carries `aria-current="page"` while the page is open
  (the row component `VF` in `app-initial-*.js` sets `aria-current` to `page` when `isActive`). The slug is a route key, not localized text, so the gate works in every locale. Static confirmation is a stock test; a narrow layout that omits the slug attribute simply has no anchor (degraded, never a guess).
- **Mount behaviour.** A `settings.section` contribution is mounted on General (`degraded:false`), unmounted (and `degraded:true`) as soon as another page is selected, and mounted again exactly once on return. `dom.observeTree` now also wakes on `aria-current` attribute changes (only that attribute), because a page switch can flip the navigation state without replacing the sections container.
- **Layout wrapper.** The mount container of `settings.section` is no longer `display:contents` (which makes the contribution a flex/grid item of the page's container) but `display:block;width:100%;min-width:0;max-width:100%;box-sizing:border-box;grid-column:1/-1` (`CONTAINER_STYLE` in `framework/renderer/mount.mjs`), independent of the parent's flex or grid layout. Other anchors keep `display:contents`.
- **Adjustments CSS.** No change needed from the static side: Adjustments' own alignment code (`alignRef`) already treats a block container as the layout parent. Native verification of the final look on General is still due.
- The 20052 pack is not changed (not the installed build, its settings structure was never verified).
- Tests: `framework/renderer/test/settings-anchor.test.mjs` (General resolves, Computer use / Agent / Plugins / no active page do not, wrapper style under flex-column, flex-row and grid parents, General → Computer use → General keeps exactly one mount with the body replaced and with only the navigation state flipped, `observeTree` aria-current wake-up) and the stock tests in `pack-tests.mjs` (gate present on all locators; slug and `aria-current` exist in the stock renderer).
