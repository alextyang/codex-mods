# Contracts

These files are the public contracts. Implement against them and change them deliberately: when a contract has to change, update the spec (ARCHITECTURE.md), every consumer and the tests in the same change. Do not work around a contract in an implementation.

| File | Defines |
|---|---|
| `../sdk/index.d.ts` | The complete mod-facing API (ARCHITECTURE §8) |
| `../sdk/errors.mjs` | `CodexModsError` and the error codes, used by every module |
| `manifest.d.ts` | `mod.json` and the `.codexmod` signature format |
| `state.d.ts` | `profile.json`, `state.json`, operation records, generations, boot markers, `InstalledMod` |
| `host.d.ts` | Module boundaries inside the Host: Bus, Mux, Runtime, Packages, Operations, Recovery, Management, `startHost` |
| `graph.d.ts` | The graph runtime (`framework/host/graph`: types, instances, the one invocation path, the intent journal, realm views) and the native protocol source. Host-internal |
| `../sdk/graph/index.d.ts` | SDK v2: the graph's definition builders and instance types (`sdk/graph/define.mjs`), and the native type library (`sdk/graph/native`) |
| `management.d.ts` | Management methods and transport framing |
| `ipc.d.ts` | framework-main↔Host messages, Realm RPC, renderer channel, socket handshakes, environment variables |
| `adapter.d.ts` | Adapter pack format |
| `layout.mjs` | Every on-disk path, socket name and flag name |
| `upstream/26.1007.21159-20052/` | The app-server protocol (JSON Schema and TypeScript) generated by the installed build's own `codex app-server generate-*` |
| `upstream/<build>/schema-experimental/` | The same schema with `--experimental` (experimental methods and fields), generated by that build's bundled `codex-cli` from a QA copy with a temporary `CODEX_HOME`. Captures and the census check experimental methods against it |

Shared helpers, held to the same standard:

- `../framework/host/fsutil.mjs`: `writeJsonAtomic`, `readJson`, `now`, `newId`.
- `../tests/fixtures/fake-app-server.mjs`: the strict fake `codex app-server` for every automated test: it refuses what it does not model, its modelled payloads match the build's schema, and it replays captures (`../tests/fixtures/captures.mjs`). Its header documents its behavior.
- `../tests/fixtures/log.mjs`: `createTestLog()`.

## Conventions

1. **Language.** ESM `.mjs` on Node 24 built-ins only. No dependencies, no build step, no TypeScript compilation. Use JSDoc type imports from these `.d.ts` files where they help.
2. **Factories.** Each module exports exactly the factory named in `host.d.ts`, from exactly the file named there.
3. **Errors.** Throw `CodexModsError` with the right code. An error that crosses a channel is `{code, message, details?}`, turned back into an error with `CodexModsError.fromJSON`.
4. **Persistence.** Use `writeJsonAtomic` for every JSON file. Never write a file in place. All directories are mode 0700, files 0600.
5. **Paths.** Use only `layout(root, profile)`. Never hard-code a home directory. Tests use a fresh `fs.mkdtemp` root.
6. **Time and ids.** ISO-8601 strings from `now()`; ids from `newId(prefix)`.
7. **Logging.** Take a `log` (`host.d.ts` `Log`) as a parameter; never `console.log` in library code. Logs hold metadata only, never message payloads, secrets or tokens.
8. **Tests.** `node:test` files named `*.test.mjs` beside the code (or in a `test/` subfolder). Each test cleans up the processes, sockets and temp dirs it created. Run them as UID503:
   `ssh <qa-host> 'cd "<checkout>" && /opt/homebrew/bin/node --test "<dir>/**/*.test.mjs"'`
9. **Fakes.** When you consume another module's interface, write a minimal fake of it in your own test folder rather than importing that module's implementation.
10. **No native app launches, no sign-in and no live model traffic** in automated tests. Native acceptance runs deliberately, on the QA machine (docs/DEVELOPMENT.md).
